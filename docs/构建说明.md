# Marco TV 构建与发布说明

作者：Pilipala · 0.14.3（正式版） · 2026-10-29

> 本软件免费开源。如果你付费购买了本软件，请尽快向购买平台申请退款。

源码使用 Java 与原生 Android API，无第三方运行时框架。包名 `com.pilipala.tvhome`，最低 API 23，目标 API 28。这里只描述当前构建路径，不表示通过应用商店新应用审核。

## Windows 便携工具链

需要 Windows x64、Python 3.10+、可访问官方分发站的网络。从仓库根目录运行：

```powershell
python scripts/bootstrap.py
python scripts/build.py
python scripts/test_motion.py
python scripts/test_release_tools.py
python scripts/check_release.py
python scripts/package.py
```

准备脚本从 Azul 与 Google 官方站下载 JDK 17、Android 28 平台、Android 35 构建工具，校验写入脚本的摘要；本地工具放在 `.tools/`，不提交到仓库。

构建脚本依次编译资源与 Java、生成 dex、对齐 APK、签名并验证。输出为 `dist/MarcoTV-版本.apk` 和 `.sha256`。打包脚本按公开文件清单生成源码与安装包 ZIP，附文件摘要清单并检查 ZIP CRC。

## 已有 Android SDK（Windows / Linux / macOS）

安装 JDK 17 和官方 Android SDK，准备：

```text
platforms;android-28
build-tools;35.0.0
```

配置 `JAVA_HOME` 和 `ANDROID_SDK_ROOT`（或 `ANDROID_HOME`），不创建 `.tools/toolchain.json` 时，构建会采用这些环境变量。工具版本可用 `MARCOTV_BUILD_TOOLS` 覆盖，默认 `35.0.0`。

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_SDK_ROOT=/path/to/android-sdk
python3 scripts/build.py
python3 scripts/test_motion.py
python3 scripts/test_release_tools.py
python3 scripts/check_release.py
```

已有 `.tools/toolchain.json` 时优先采用该本地配置；移动项目目录后可重新运行准备脚本。跨平台路径已经实现，当前作者本地验收为 Windows；其他平台应自行验证构建结果。

## 签名与覆盖安装

默认首次构建在 `private/development.p12` 生成本机开发密钥，开发口令为 `android`，不可公开上传这个私钥。后续本机构建复用它以支持覆盖安装；作者公开 APK 也保留既有签名。新电脑自动生成的密钥与官方包不同，不能直接覆盖官方包。

正式维护自己的分支时，创建并妥善备份独立签名文件，可通过环境变量指定：

| 变量 | 用途 |
| --- | --- |
| `MARCOTV_KEYSTORE` | 已存在的签名文件路径 |
| `MARCOTV_KEY_ALIAS` | 别名，默认 `tvhome` |
| `MARCOTV_STORE_PASSWORD` | 签名口令，默认仅为本机开发值 |

脚本通过环境传给签名工具，不把口令拼进公开仓库。不要把私钥、密码、GitHub Token 放进代码或 Issue。打包时不包含密钥，别人自行构建也不应使用作者私钥。

## 测试与公开检查

`test_motion.py` 运行焦点动画的轨迹检查；`test_release_tools.py` 验证内存数据解析与汇总；`check_release.py` 核对许可、源码署名、版本、文档相对链接和公开文件范围。它们不能代替实体电视、Home、Wi-Fi 或重启测试。实际验收边界见[验证范围](验证范围.md)。

GitHub Actions 的 Windows 构建使用新生成的临时开发密钥，产物只用于构建检查，不会自动替代作者签名的 Release。工作流不需要作者签名密钥或仓库写权限。

## 连接电视的针对性回归

先使用同一私钥构建并安装当前 APK，按安装说明启用正在播放卡片并授予通知使用权，然后运行：

```powershell
python scripts/test_device_regressions.py --adb adb --serial YOUR_DEVICE
```

这会临时安装独立测试 APK，重启 Marco TV 并打开菜单，强制覆盖启用缓存的分支，检查重新导入封面、应用图标失效以及系统设置 / 权限回调在 Home 后被丢弃。临时封面和测试 APK 会被清理，原有卡片和设置不变。部分固件在测试重启后保留失效的无障碍连接；脚本仅在原先已启用且设置未被用户修改时重连 Marco TV 的 Home 服务，保留其他服务。测试必须在方便使用电视时执行。

当前脚本含 73 项检查，包括排序、手动公开入口、隔离配置中的备份恢复 / 拒绝坏文件 / 中断回退、日志保留上限与无声音的测试媒体会话；测试会话结束后会释放，不恢复或暂停用户实际媒体。

测试程序用本机真实 Android API，但通过受控回调验证导航逻辑；它不是 Android 10 以上系统 Wi-Fi 面板的实机兼容证明。详细边界见[验证范围](验证范围.md)。

## 内存采样与比较

先安装需要测量的版本、手动打开桌面，保持相同壁纸、应用数量、屏幕状态与等待时间。设备需已连接并授权 ADB。脚本只读采样，不安装应用、不切换默认桌面、不触发强制回收。

```powershell
python scripts/measure_memory.py --adb adb --serial YOUR_DEVICE --samples 12 --interval 5 --label idle-desktop --output build/memory-before.json
# 手动安装后一个版本，以相同条件再次打开桌面，再执行：
python scripts/measure_memory.py --adb adb --serial YOUR_DEVICE --samples 12 --interval 5 --label idle-desktop --output build/memory-after.json --compare build/memory-before.json
```

`YOUR_DEVICE` 替换为自己的设备标识，ADB 不在 PATH 时用 `--adb` 指定路径。不要把设备地址、Wi-Fi 名称写入场景标签。输出不包含设备标识或原始系统日志，只保留版本、采样时间、场景和内存指标。两份报告须来自同一设备；脚本只能检查采样次数、间隔与标签，不能代替操作者确认。

全部样本与最小值、中位数、采样最大值、首尾值均保留。PSS 是分摊共享内存后的占用；private 是表格中的 private dirty 加 private clean，并非整个设备内存。采样最大值不是采样间隙内的真实峰值，短时间数据不能证明帧率或长期稳定。进程重启、读取失败或格式无法识别会中止，不把缺失数据记成零。

## 修改版本与打包

同时更新 `app/src/main/AndroidManifest.xml` 的 `versionCode` / `versionName`，以及 `ProjectInfo.java` 的版本常量，再更新文档。构建脚本会检查应用版本一致，并从根目录同步许可到应用离线资源。

公开清单在 `scripts/public_files.py`。源码包包含应用、资源、许可、文档、通用构建与授权脚本，不包含本机实验、原始设备日志、网络配置、内部研究材料、第三方安装包或工具缓存。APK 单独附于 Release，不把生成二进制反复提交进 Git 历史。

发布者应先完成相关测试，再校验签名与摘要，创建对应源码标签，发布 APK、SHA-256 和包含源码的 ZIP。发布修改版时保留 Pilipala 原署名、注明修改，不冒充作者官方构建。

## 任务辅助服务测试

先按安装说明启动任务服务，再执行以下任一检查。使用与安装包相同签名的临时测试 APK，测试结束卸载；不会移除用户现有任务。

```powershell
python scripts/test_device_regressions.py --adb adb --serial YOUR_DEVICE --bridge-only
python scripts/test_device_regressions.py --adb adb --serial YOUR_DEVICE --task-actions
```

第一组核对连接、版本、任务编号及非法编号拒绝；第二组创建同一测试应用的两个真实任务，验证分别保留、精确切换、界面显示和系统移除能力。系统不开放移除时验证请求拒绝且两个任务均保留，最后卸载测试 APK 清理测试任务。

## 设置迁移检查

运行 `python scripts/test_settings.py`，在不连接电视的情况下验证旧菜单合并、排序保留和升级幂等性。`python scripts/test_device_regressions.py --serial YOUR_DEVICE` 在已安装同签名应用的电视执行完整检查（85 项），使用隔离数据验证新旧备份恢复，不覆盖用户配置。新增 `--compile-only` 可仅编译测试包，不连接电视；编译成功不等于实机通过。

## 发布更新索引

运行 `python scripts/test_updates.py` 验证更新策略。更新设备检查通过 `test_device_regressions.py --updates-only --candidate DEVICE_PATH --wrong-signer DEVICE_PATH --adb ADB --serial DEVICE` 执行：使用一个更高版本的同签名候选 APK 和同包名同版本的不同签名测试包，仅验证，不安装测试包。

`make_update_feed.py` 从已签名 APK 生成 metadata，读取真实 versionCode、versionName、minSdk、大小和 SHA-256；命令参数见 `--help`。先发布 APK，再核对公开下载与 GitHub 资产摘要，最后发布 `docs/updates/stable.json` 或 `preview.json`。稳定索引不得指向预发布包；体验索引不得伪造 versionCode。稳定渠道保持最近稳定版，只有正式稳定发布后才推进。索引与下载包摘要必须对应，不能把 CI 临时签名包当作官方更新。

索引更新与发布 APK 可为独立提交；索引更新不修改已经发布的 APK。GitHub Pages 可能有缓存，须验证部署后内容。客户端拒绝低版本、非官方下载路径、非 HTTPS、错误签名与错误摘要。

镜像发布与故障回退见[镜像更新部署](镜像更新部署.md)。

Marco 互联的二维码编码采用随源码附带的 Nayuki Java 实现，MIT 许可保留在 `licenses/QR-Code-generator-MIT.txt`，无额外在线构建依赖。运行 `python scripts/test_phone_http.py` 检查传输层；连接测试电视后可使用 `scripts/test_device_regressions.py --phone-only --serial <电视地址:端口>` 检查配对、预览与保存，测试会恢复原设置。
