# Marco TV 镜像更新部署

作者：Pilipala · 0.12.0-rc.4 · 2026-10-27

镜像地址：https://marcotv.wlj9919.top/ 。客户端从 rc.4 起优先使用镜像，失败时尝试 GitHub。此文与部署 ZIP 只交付静态文件，不代表镜像已经更新。

## 文件布局

保留原站首页、图片等文件，把部署包内容合并到网站根目录。Cloudflare Pages 等整站部署平台需要合并后再部署完整网站，不能只上传覆盖包而丢失原网站。

```text
网站根目录/
  MarcoTV-0.12.0.apk
  MarcoTV-0.12.0.apk.sha256
  MarcoTV-0.12.0-rc.4.apk
  MarcoTV-0.12.0-rc.4.apk.sha256
  updates/
    stable.json
    preview.json
```

stable 保持已验证的稳定版本，preview 提供体验版。不要把体验版直接放入 stable。0.11.1 没有在线更新，需要用户先手动安装带更新模块的版本。

## 生成与发布

1. 完成构建和验证，在 GitHub 发布对应 APK 与同版本源码包。保留同一签名，已发布的版本文件不能替换成另一份内容。
2. 用 `scripts/make_update_feed.py` 从实际签名 APK 生成版本索引，校验版本号、大小和 SHA-256，不手填虚构版本码。
3. 将 stable 和 preview 对应 APK 放入 dist，再生成部署包：

```powershell
python scripts/package_mirror.py --output dist/MarcoTV-mirror-overlay.zip
```

4. **先上传 APK，确认完整下载与摘要一致，再上传 JSON 索引。** 若平台支持原子部署，可同一次完整部署，仍需上线后验证。索引最多缓存 5 分钟；版本 APK 可长期缓存，但不得修改。
5. 保留源码下载链接及 LICENSE、NOTICE。镜像首页应继续链接同版本 GitHub 源码包；若自行修改软件，需同步提供相应源码。

## 服务器要求

- HTTPS 证书有效，不要求账号、验证码、浏览器验证、Cookie 或 Referer。不要对 `/updates/` 与版本 APK 启用 JavaScript 挑战。
- `/updates/stable.json` 与 `/updates/preview.json` 返回 JSON，建议 `Content-Type: application/json`、`Cache-Control: public, max-age=300`。
- 不存在的更新索引或 APK 应返回 404，不能返回首页 HTML。检查站点的单页应用回退规则。
- APK 返回正确 `Content-Length`；支持 `Range: bytes=N-` 时应返回 206 和匹配的 `Content-Range`，内容不得压缩或重新打包。不支持 Range 时可返回完整 200，客户端会从头重下。
- 网站后台和发布凭证只用于部署，不放进 APK 或公开仓库。电视只读取公开文件。

## 验收与限制

分别在电脑和电视网络验证两个 JSON、完整 APK 下载、断点续传和 SHA-256；浏览器能打开首页不能替代这些验证。镜像使用 Cloudflare 也不意味着所有国内网络都能稳定访问。

客户端在镜像索引超时、返回网页或不合法时回退 GitHub。镜像返回合法但较旧的版本时会按该索引处理，因此每次发布必须同步索引。下载会先尝试镜像，同一 APK 可跨来源续传；完整文件仍需通过摘要、包名、版本和已安装软件的签名校验。镜像内容错误时丢弃错误文件，再尝试官方来源。两个来源都失败时保留现有软件，网络中断的部分下载可重试。

所谓“推送更新”在此是电视定期检查公开版本索引：至少间隔 6 小时，用户也可手动检查。自动下载需用户选择，最终安装仍由用户确认；不提供远程静默安装。更新后系统任务辅助服务仍需电脑重新启动。
