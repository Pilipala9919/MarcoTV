## 1. 架构决定

### 动态背景

- P3 原型使用 Android 平台 `MediaPlayer`，仅播放已校验的本地 MP4/MOV 文件；不引入 Gradle、不添加媒体网络框架。复杂流媒体格式不在第一版范围。
- 默认先验证 `SurfaceView`：全屏视频不做旋转与 3D 投影，上方保留透明 UI、遮罩和静态封面。P3 与 TextureView 实测比较后再确定正式输出方式；P0 没有宣称已完成这项对比。
- `HomeView` 当前会先画黑底再画图片，不能简单在后方添加视频 View。P3 必须分离背景绘制与卡片/时钟绘制，同时保留静态模式现有路径。
- `MarcoDreamService` 和应用内 `IdleController` 是不同宿主，共享一个进程级视频资源协调器。任何时候最多一个播放器对象进入准备或播放。
- `BackgroundPlaybackSession` 已落地，负责资源交接协议；Android 适配器后续负责实际创建、释放、超时和 Surface 生命周期。单元测试不能证明厂商解码器不会卡死。
- `MediaPlayer` 的创建、方法调用和回调串行放到专用 HandlerThread。不得在 UI 绘制、遥控器事件或主线程中执行阻塞准备/释放；不得配置后台音频焦点或额外唤醒锁。
- P0 只定义“停止播放并释放”路径，不提供持有解码器的无限暂停。遮罩或短暂菜单出现是否释放，按宿主可见性规则统一决定。

### 天气

- `WeatherRefreshPolicy` 已落地，负责城市代次、请求去重、取消、刷新间隔、服务端退避和数据新鲜度。
- 后续 `WeatherRepository` 单独管理网络与缓存，不共用壁纸解码或应用加载队列。UI 只读不可变快照。
- 当前用 `home` 偏好保存外观，新的城市和联网同意保存在独立 `weather` 偏好；外观备份不携带城市、定位授权和配对票据。
- 手机定位采用独立 HTTPS 页面和短时票据传递城市。保留现有局域网配对 / Host / Origin / CSRF 校验，不为跨源定位放宽它们。

## 2. 已实现的播放协议

文件：`app/src/main/java/com/pilipala/tvhome/BackgroundPlaybackSession.java`。

所有方法由同一个串行执行环境调用。`Request` 包含：

| 字段 | 含义 |
| --- | --- |
| owner | DESKTOP / DREAM / PREVIEW |
| asset | 内部素材标识，最长 128 字符；不是文件路径、URL 或用户文件名 |
| surfaceGeneration | 进程全局递增的 Surface 代次；宿主重建不能从 1 重新开始复用 |

`owner()` 的优先顺序为：关屏无所有者 → 已显示的 Dream → 显式播放预览 → 可见桌面。静态模式不播放桌面/Dream，但允许用户主动的独立视频预览。

调用约定：

| 事件 | 输入 | 适配器执行 |
| --- | --- | --- |
| 模式、素材、可见性或 Surface 改变 | `update(request)`，不可播放时传 null | 根据 Command 执行；NONE 不创建任何资源 |
| PREPARE | 命令内 token 和 Request | 创建唯一播放器，设置静音、Surface、本地来源并异步准备 |
| 平台准备完成 | `prepared(token)` | START 时启动；封面仍然显示 |
| 真正输出首帧 | `firstFrame(token)` | SHOW_VIDEO 时淡出封面；不是 onPrepared 就宣称画面可见 |
| 错误或准备/首帧超时 | `failed(token)` | RELEASE；静态封面可见 |
| 停止、换宿主或关屏 | RELEASE | 隐藏视频并真正释放对应播放器；只在完成后回调 `released(token)` |
| 用户显式重试 | `retry()` | 失败状态可产生新的 PREPARE；旧失败不会不断自动重试 |

状态：IDLE → PREPARING → STARTING → PLAYING；中途退出或错误进入 RELEASING。收到真实释放确认后才允许下一次 PREPARE。错误素材进入 FAILED，直到换请求或显式重试。

重要约束：

- 任意异步回调同时带 Command.token，过期回调不能显示旧视频。
- RELEASE 进行中反复切换，只保留最后一个期望请求。
- 错误的释放 token 不会释放新会话；同一会话重复 prepare 不会创建第二个对象。
- 释放卡住时保持静态背景，不能伪造 released 回调后另开第二个解码器。记受限错误码并在下次正常进程启动后恢复。
- P3 初始超时建议：本地准备 8 秒、启动后首帧 5 秒。计时应带 token，后台/销毁后取消，不从过期定时器影响新播放器。
- `showVideo()` 只表示逻辑首帧状态；Surface 实际就绪、渲染层级、黑帧和色彩必须实测。
- 无法确认 Surface 是否安全销毁时，保持封面直到释放完成；具体平台回调策略由 P3 实现并测试。

## 3. 天气刷新协议

文件：`app/src/main/java/com/pilipala/tvhome/WeatherRefreshPolicy.java`。

`select(provider + ':' + cityId)` 只接收已确认的城市。切换城市或清除城市会使旧请求失效。重复选择同一城市不重置限流。

宿主隐藏、天气关闭或销毁时必须调用 `cancel()`，并取消实际网络调用。策略 token 只能阻止旧结果生效，不能自动关闭网络连接；即使取消不成功，也不得允许旧响应覆盖 UI 或持久缓存。

`begin(enabled, visible, online, nowElapsed, matchingFreshCache, manual)` 返回 0 表示不发请求；其他值作为该次请求 token。收到响应经严格校验后，再用 `complete(token, nowElapsed, success, retryAfterMs)` 判断能否提交。

- 初始自动刷新间隔 30 分钟；成功返回旧观测数据也不能变成每分钟自动请求。
- 手动刷新至少间隔 60 秒，且不能绕过服务端 Retry-After。
- 服务端要求超过 6 小时的退避也必须保留，不能截短；deadline 运算防溢出。
- `freshness` 按服务商观测时间判断：不足 30 分钟为 FRESH，30 分钟至 6 小时为 STALE，超过 6 小时为 EXPIRED，缺失时间或超前超过 5 分钟为 UNKNOWN。
- 返回时间戳、接收时间与 monotonic 请求计时分开。跨进程不能直接复用旧 elapsedRealtime deadline；服务端长退避需持久化到 UTC 截止时间，并在进程启动时转换和校验。
- 策略中的初始 TTL 可在接入真实服务商后收紧；不覆盖供应商更严格的缓存要求。
- 缓存只能在城市与服务商匹配时标记 matchingFreshCache；显示过期内容需标注更新时间，EXPIRED 不继续显示成“当前天气”。

## 4. 提供给 Sol 的服务接口 v1

路由前缀建议 `/api/weather/v1`，与 `/api/feedback` 隔离。此处是接口约定，尚无线上实现。

| 路由 | 请求 | 响应与限制 |
| --- | --- | --- |
| GET /config | 无城市信息 | schema、ready、provider、refreshSeconds、来源说明；未配置返回 ready=false |
| GET /cities?q=... | 1–64 字符，去除控制字符 | 最多 10 个城市，包含省份/国家用于区分重名；不接受任意上游 URL |
| POST /suggest-city | 用户主动请求；不传电视标识 | 服务端网络位置候选，可能为空；Cache-Control: private,no-store，禁止公共缓存 |
| GET /forecast?city=... | 由本服务生成的规范 cityKey | 天气快照；缓存按服务商、城市和单位划分 |

响应 JSON 上限：天气 64 KB，城市列表 16 KB，错误 4 KB。客户端连接超时 8 秒、读取超时 10 秒；禁止跟随到不可信来源的重定向。字段长度、数字有限性、数组数量、时间戳和城市回显需校验。

天气快照 v1：

```json
{
  "schema": 1,
  "location": {
    "key": "provider:city-id",
    "name": "城市名",
    "region": "省份",
    "country": "CN",
    "timezone": "Asia/Shanghai"
  },
  "current": {
    "observedAt": "2026-11-03T12:00:00Z",
    "temperatureC": 18.0,
    "feelsLikeC": 17.0,
    "condition": "cloudy",
    "isDay": true,
    "humidityPercent": 60,
    "windKmh": 8.0
  },
  "daily": [
    {"date": "2026-11-03", "lowC": 12.0, "highC": 21.0, "condition": "cloudy"}
  ],
  "meta": {
    "provider": "provider-id",
    "fetchedAt": "2026-11-03T12:05:00Z",
    "refreshAfterSeconds": 1800,
    "attribution": [{"label": "供应商名称", "url": "https://example.com"}]
  }
}
```

上例是格式示例，不是真实天气或指定供应商返回。`current` 可为 null；体感、湿度、风力允许 null；daily 最多 3 项，缺失数据不填 0。condition 固定为 clear/cloudy/fog/rain/snow/sleet/thunder/unknown，供应商编码在服务端映射，未知情况不猜测。数值合理性界限由解析器校验，例如温度 -100～70℃、湿度 0～100%、风速 0～500 km/h。来源链接仅允许可信 HTTPS 域名。

错误格式：`{"schema":1,"error":{"code":"UPSTREAM_UNAVAILABLE","retryAfterSeconds":60}}`。code 允许 NOT_CONFIGURED / INVALID_CITY / NO_LOCATION / RATE_LIMITED / UPSTREAM_UNAVAILABLE / INVALID_RESPONSE。不得回传服务密钥、原始网络异常或用户 IP。

同城缓存需防并发请求穿透，provider 配额和来源请求限流分别设置。缓存的 fetchedAt 保留原抓取时间，不随每次命中刷新。收费阈值达到时返回受控错误；不自动购买套餐。

## 5. 手机定位通道决定

采用“电视主动发起 → 手机 HTTPS 授权 → 电视确认城市”的独立流程，不跨域请求电视 HTTP 接口。

1. 用户在电视点击“手机定位”，电视通过 HTTPS 创建 5 分钟会话。
2. 服务生成 sessionId、phoneSubmitSecret、tvPollSecret；各自使用至少 192 bit 安全随机数。后两个权限严格分离，服务端仅存令牌哈希。
3. 二维码指向 HTTPS 页面，手机凭据放 fragment；页面读取后清除地址栏 fragment，不载第三方脚本或追踪器。tvPollSecret 不进入二维码。
4. 手机点击定位并授权浏览器后，坐标仅用于服务端反查城市，不写入报告或日志；拒绝时可在手机手动搜索城市。
5. 手机只能提交由服务验证过的候选城市；单次候选提交通过事务限定。电视用自己的凭据轮询到候选，界面显示省、市和国家。
6. 用户在电视确认后保存城市，并消费会话；取消、超时或应用退出则注销会话，不改变原城市。
7. 轮询只在该页可见时进行，建议 3 秒一次、上限 5 分钟，429 后按退避。没有公网入站访问电视的需要。

建议接口：POST /location-sessions（创建）、POST /location-sessions/resolve（手机短暂坐标反查）、POST /location-sessions/submit（候选）、POST /location-sessions/poll（电视轮询）、POST /location-sessions/close（确认或撤销）。所有响应 no-store；凭据用请求体或 Authorization，不用 URL query，不写日志。

会话表独立于反馈 reports；创建限流、每 IP 短时最多 3 个活动会话、全局配额上限和过期清理均需实现。过期会话即使物理删除尚未发生也不能读取或消费。展示的是城市，不建立长期设备账号。

这一通道属于 P2，可晚于 P1 交付。P1 不依赖它，用网络推荐和电视手选完成天气闭环。

## 6. 设置与持久化责任

以下键为约定，尚未写入应用偏好或备份白名单；Sol 接入时一次性完成范围校验和迁移。

| 存储 | 键 | 默认与范围 | 备份 |
| --- | --- | --- | --- |
| home 外观草稿 | background_mode | int 0 静态 / 1 仅屏保 / 2 持续；默认 0 | 可 |
| home 外观草稿 | weather_visible | boolean false | 可，但无城市时显示待设置而不定位 |
| home 外观草稿 | weather_size | int 100，75–150% | 可 |
| home 外观草稿 | weather_position | int 0 日期下 / 1 日期旁 | 可 |
| home 外观草稿 | weather_detail | int 0 简洁 / 1 扩展 | 可 |
| weather | enabled、consent_version、city_key、city_label、timezone | 开启联网、同意版本和已确认城市 | 不随外观备份 |
| 独立素材仓库 | active_asset、quality_preference、cache_limit_mb | asset 可空；auto/1080/4k；缓存默认 512 MB | 保存描述，不打包视频或路径 |
| noBackupFilesDir | 天气缓存、定位短时票据 | 退出/过期清除票据；缓存按 city/provider 验证 | 否 |

background_mode 和 active_asset 要在同一次外观提交中协调，素材文件先准备好、再发布引用；失败时保留旧设置。取消只能删除本次导入的临时文件。手机上传遇到电视编辑草稿时继续返回冲突提示，不能直接写正式偏好。

选到缺失素材时运行态回退静态，不偷偷清除用户选择。备份恢复只保留素材描述，不接受包内任意路径、未经验证 URL 或之前的访问凭据。

## 7. 基线、预算与完成证据

实测设备：已有小米电视 / Android 9，安装的是既有 0.15.0 反馈测试包；本轮未安装新 APK。原始截图和设备采样留在私有验证目录，不进入公共仓库。

- 初始和只读采样结束时：Marco TV 在前台、Home 服务已绑定、任务辅助服务运行。
- 静态应用内时钟屏保，6 次采样、间隔 5 秒、同一进程：PSS 中位数 40,080 KB（约 39.1 MiB），范围 40,060–44,117 KB。
- 此为短窗口静态基线，不是长期内存泄漏检查，也不是视频播放器内存预算。
- 最初 dumpsys gfxinfo 包含数千帧历史操作，不作为新功能滚动对比基准。
- 单轮卡片滚动基线：清空帧计数后，执行 32 次方向键（右、右、左、左重复 8 次），共 43.71 秒，同一应用进程；记录 1,618 帧，卡顿 2 帧（0.12%），p50 / p90 / p95 / p99 为 7 / 10 / 11 / 13 ms。结束截图确认仍在桌面卡片行。
- 上述是一次 ADB 操作下的 HWUI 样本，包含命令传输间隔；不是实体遥控器延迟，不包含视频解码，不是三轮性能验收。P3 比较前须按同样流程重新取得三轮配对静态样本。

本地完成检查：

- 正常版全部 Java 源码编译通过，输出到独立验证目录；未重新打包或覆盖稳定版 APK。
- 新增背景/天气策略 64 项检查通过，包括 2,000 次事件的资源交接轨迹；原有核心一致性 35 项检查通过。

- 滚动采样后再次只读核对：电视亮屏、Marco TV 前台，HomeKeyService 进程与系统绑定连接存在，任务辅助服务运行。未改写权限或恢复设置。
- 没有完成新播放器解码、真实天气、手机 HTTPS 定位、实体遥控器或断电重启验收；这些仍按后续阶段执行。

P3 初始工程验收预算（需同机、同场景成对比较）：

- 功能关闭时保持静态路径，空闲 PSS 中位数新增不超过 8 MiB；超出先查常驻对象与缓存，不直接提高预算。
- 1080p 播放的总内存由解码器与合成层决定，不套用静态 39 MiB 限制。记录播放峰值及退出后恢复，30 分钟稳定运行和 20 次切换后检查是否持续增长。
- 连续 20 次切换后回到同一静态场景，稳定 PSS 中位数目标不高于新包静态基线 8 MiB。PSS 存在噪声，异常需重复同场景确认。
- 卡片滚动同一脚本跑 3 轮：p95 不比静态基线增加超过 3 ms，卡顿比例不增加超过 2 个百分点；这是项目初始退化门槛，不是声称现有桌面全程 60 fps。
- HWUI 帧统计不包含独立视频 Surface 的全部解码质量；还需解码丢帧、真实录像及主观观感检查。
- Home 服务、默认桌面模式或恢复暂停状态一旦发生非预期变化，立即停止该轮性能验收并优先恢复用户配置。
