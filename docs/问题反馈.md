# Marco TV 问题反馈

Pilipala · 2026-11-03 · 功能开发验证中 · GPL-3.0-only

本轮不改变公网 0.15.0 安装包。接收端和手机页已部署，电视功能在独立命名的开发测试包中验证；正式升级需随下一版发布。

## 电视用户

在「设置 → 维护与帮助 → 本地诊断 → 问题反馈」预览报告，选择在电视确认提交，或生成二维码用手机确认。二维码包含脱敏报告，不要公开转发。收到服务器回执后才显示成功和编号。

手机可补选 Home、开机、最近任务、动效、网络或其他分类。不要求注册账号、不索要密码和联系方式。若服务暂不可用，页面如实显示未提交；电视保留一个最大12KB的待提交文件，可重试或清除。重试沿用原编号，避免重复写入。新的手动报告不覆盖尚未提交的旧报告。

「查询最近反馈进度」只显示已收到、排查中、已处理；收到不代表已经修复。作者更新状态后，用户再查询才能看到进展。

## 自动提交

默认关闭。用户单独同意后，仅在本地诊断也已开启且发现异常时尝试，每24小时最多一次；相同版本与故障代码、代码位置组合去重。程序被系统完全禁止启动或没有网络时不能保证发送；它不是其他应用的系统级崩溃收集器。

关闭后尝试中断网络连接，并清除尚未发送的自动报告；已经到达的反馈不能通过关闭开关撤回。报告与同意状态不参与配置备份迁移。用户关闭本地诊断也会停止自动提交。

## 报告范围

仅含随机报告编号、版本/版本类型、厂家、型号、固件、Android API、HOME及自身服务状态、最多20个允许的事件代码和最多12个本应用代码位置。扫码压缩版最多3个代码位置。不传异常消息、账号、序列号、MAC、家庭IP、Wi-Fi、媒体内容、截图或完整应用列表。

Cloudflare 仍处理请求的来源IP等网络信息；数据库仅保存每小时变化的限流摘要，不保存原始IP。编号30天后不再查询，过期记录在收到新反馈时清理；当前不是定时物理删除。详见[隐私说明](隐私说明.md)。

## 接收端部署

`feedback/functions` 是 Cloudflare Pages Functions，复制为镜像仓库根目录 `functions`；`feedback/web` 复制为镜像站 `feedback`。保留已有下载包、更新索引、Lite和其他产品目录。

1. 创建专用 D1 数据库，执行 `feedback/schema.sql`。
2. 在 Pages 生产环境绑定 `FEEDBACK_DB`，仅指向此专用库。
3. 配置 `FEEDBACK_RATE_SALT` 为至少32字符的随机密钥，只存于服务器。它用于限流摘要，不能写入APK、仓库或日志。
4. 重新部署。`GET /api/feedback/config` 应返回 JSON `{ready:true,schema:1,...}`；缺绑定、缺密钥、未建表时返回503，不得用静态404页面当成成功。
5. 使用模拟数据验证提交、重试同编号、查询、未知字段拒绝、请求限流及服务故障状态。不要用真实用户报告做公开测试素材。

正文接收仅支持同源网页或原生客户端的 JSON POST，最大12KB，字段白名单与参数化SQL。每个请求来源的小时限流为20次新报告；此为基础防滥用，不是严格的客户端身份认证。没有在APK内嵌共享API密钥，也没有公开读报告正文的接口。

## 作者排查

登录 Cloudflare 后，从 D1 → 专用反馈库 → 控制台查看；不需要建立公开管理后台。按机型和事件筛选，关注相同固件的重复问题。一次报告中的随机编号不能当作独立用户数或装机量。

```sql
SELECT id, datetime(created_at / 1000, 'unixepoch') AS received,
       json_extract(payload, '$.manufacturer') AS manufacturer,
       json_extract(payload, '$.model') AS model,
       json_extract(payload, '$.firmware') AS firmware,
       json_extract(payload, '$.events') AS events, state
FROM reports WHERE expires_at > unixepoch() * 1000
ORDER BY created_at DESC LIMIT 50;
```

确认开始排查后，按完整编号使用参数或精确条件更新 `state='investigating'`；真正完成后改为 `resolved`。不要把全部报告批量标成已解决。当前不会自动发邮件或通知第三方。

## 验证入口

- `python scripts/test_feedback.py`：实际Java过滤策略、实际服务端处理器与内存SQLite、手机页面状态逻辑。
- `python scripts/test_feedback_transport.py`：实际电视传输代码，使用隔离的 Android 服务替身和HTTPS响应，覆盖默认关闭、失败保留、编号重试、无效回执、响应上限与关闭行为。
- `python scripts/test_home_setup_device.py --feedback --adb <adb> --serial <电视>`：真实电视界面与模拟报告上传，不替用户开启自动提交，结束后恢复反馈偏好。

设备检查需要电视亮屏、没有其他测试运行，并取得用户允许。测试使用模拟厂家/型号/故障内容；不把用户原始截图放进公开素材。
