## 适合什么情况

电视安装正常版时，报错包含 `disable install launcher app not signature by tcl`，可以测试此包。这是针对带 HOME 声明的应用被固件拒绝安装的适配方向；不代表所有 TCL 都需要此包，也不保证能解决其他安装限制。

本次测试包为 `MarcoTV-0.14.4-Restricted.apk`，Android 6.0 及以上，包名仍为 `com.pilipala.tvhome`，使用 Pilipala 原有签名。它沿用开发中的 0.14.4 版本号，包含尚未正式发布的桌面启用流程；不能视为公网正常版 0.14.4 的同一文件。Lite 仍是独立的老系统版本。

## 第一步：只验证能否安装

1. 下载测试包和校验文件；把安装目标核对为实际电视，而非路由器。
2. 使用电视已提供、已允许的安装入口。如果用 ADB，按电视提示允许连接；如果授权框不出现，可先回原厂主页重试。这是排查方法，不保证每个型号都适用。
3. 安装本测试包。记录完整安装结果，不要删掉原厂桌面或其他辅助服务。
4. 成功后从原厂应用列表打开 Marco TV，先检查方向键、返回、打开应用、卡片、时钟和 Marco 互联。

仅有 HOME 签名报错的变化，不能证明所有安装限制都已解除。若仍被拒绝，请提供完整报错。不要为试包额外关闭安装校验、刷机或修改不明系统属性；安装开关已变更的设备，应根据之前记录的原值恢复，未知原值不要猜测。

如原本没有安装 Marco TV，不存在覆盖数据的问题。如果已有官方同包名版本，应先在应用中导出备份，再覆盖安装；签名冲突时停止，不要直接卸载。第三方自行重签的包不能按官方同签名包处理。

## 第二步：检查 Home 兼容

1. 进入「设置 → 系统与启动 → 桌面启用与检查」。顶部应出现「受限系统兼容版 · 无系统默认桌面入口」。关于页也会标明兼容版。
2. 点击「开始设置」，按提示进入 Home 兼容。需要时在系统辅助功能中开启 Marco TV 对应服务。
3. 打开另一个应用，短按 Home；记录是否返回 Marco TV、是否闪过原厂桌面。再检查返回键和方向键是否正常。
4. 双击、长按 Home 按当前设置分别检查；若系统未将按键交给辅助服务，本版本无法保证接管成功。
5. 在方便时关屏并唤醒，最后进行一次实际重启。开关屏不算重启。分别反馈是否自动回来、服务是否仍连接、按键是否正常。

本版没有系统默认桌面资格。能安装、Home 能返回、开机能进入是三个不同结果。兼容设置和开机请求也可能被厂商限制。暂停自动恢复可从「更多设置方式」操作；原厂桌面一直保留。

实验性的本机增强设置仍需电视系统确认。兼容版只尝试自身系统设置授权，不执行 `set-home-activity`。授权成功后仍需返回启用 Home 兼容；它不会自动开启持续 ADB 恢复。

## 更新与版本切换

兼容版检查 `restricted-stable.json` / `restricted-preview.json`，只接受 `-Restricted.apk` 下载地址、`edition: restricted` 的索引和具有相同标识、相同签名的 APK。正常版更新检查会拒绝兼容包。

本次没有发布兼容版更新索引或上传镜像站。自动检查可能提示「兼容版更新暂不可用」；这不代表需要改装正常版。测试阶段使用后续明确提供的兼容测试包覆盖更新即可。未来覆盖更新需保持相同包名、签名和适当版本号，不必每次卸载。

两个版本包名相同，不能并排安装。手动安装是系统行为，应用内更新检查不能阻止用户在文件管理器主动选择其他包；在受限电视上请始终使用兼容包。

## 开发者构建

```text
python scripts/build.py
python scripts/build.py --restricted
python scripts/test_restricted.py
python scripts/test_updates.py
```

兼容版从同一份源码构建，构建时移除 HOME alias 并写入编译标志及包内标识。不对已签名 APK 做反编译和重签处理。版本发布前仍需更新验证记录、版本号、对应源码与专属更新索引。

将来发布兼容版索引时，使用 `make_update_feed.py --restricted`，输出名称为 `restricted-stable.json` 或 `restricted-preview.json`。生成器会核对包内兼容标识并拒绝含 HOME 声明的兼容包，不会修改现有正常版更新索引。
