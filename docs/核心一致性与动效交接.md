# 核心一致性与动效交接

Pilipala · 2026-11-02—2026-11-03 · 基于 0.14.4 后续开发代码，未发布新版本。

## 本轮已经实现

### 外观编辑统一事务

`AppearanceSession` 管理 Magic Desktop 及其壁纸、屏保子页的同一次编辑。`PreviewPreferences` 支持整数、字符串和布尔值，仍保持只读接口；明确保存时才通过单个 Editor 写入编辑过的键。

- 壁纸选择、恢复默认壁纸的压暗值、屏保开关及休眠时长都进入草稿。
- 系统屏保配置仅在保存后应用；取消不会改动系统屏保配置。
- 本地导入使用独立图片文件，预览不会覆盖当前正式壁纸。保存时在同目录原子替换为 `wallpaper-image`，保持现有备份格式兼容；取消删除本次新导入的文件。替换失败保留编辑页和原壁纸。
- 保存按钮在图片读取完成前不关闭编辑页；取消仍然可用。
- 异步图片返回检查编辑会话、菜单代次及壁纸选择版本，过期结果被丢弃。
- 不将尚未提交的图片选择跨 Activity 重建恢复成正式修改。
- 手机上传壁纸、导入备份在电视编辑外观时拒绝执行，提示先保存或取消。

主要文件：`AppearanceSession.java`、`PreviewPreferences.java`、`PersonalizationPanel.java`、`SettingsNavigator.java`、`CoverManager.java`、`PhoneManager.java`。

### 桌面恢复入口收敛

系统与启动中的恢复入口调用 `DefaultHomePanel.restore()`，与一键设置向导共用 `HomeSetupSnapshot` / `LocalHomeAuthorizer` 的恢复路径。

移除了旧入口顺带关闭屏保、恢复历史竞争辅助服务的实现。有快照时按快照恢复；没有快照时提供明确的暂停与系统桌面选择入口，不猜测用户原配置。壁纸、屏保和其他应用辅助服务不属于本次恢复范围。

这里的“恢复设置前”仍不等于“保证切回某个厂商桌面”：最终以系统 HOME 解析、服务状态及实体按键结果为准。

### 加载队列与最近任务

- 应用目录、壁纸、任务列表、任务截图各有独立 `LatestTaskQueue`，每个队列最多一个正在执行和一个最新待执行读取。
- 新读取替代尚未开始的旧读取；正在执行的读取在检查点退出，提交结果时再次验证归属。
- 任务切换和清除使用独立命令执行器，不再等待壁纸、应用目录和整批截图。
- 最近任务先提交名称 / Logo 列表，再读取选中项及前后相邻截图，移动焦点后更新读取优先级。
- 刷新按 taskId 保留焦点；任务消失时选择相邻位置。`TaskSelection` 有独立边界测试。
- 离开最近任务或退出相关预览后，取消待执行读取，过期截图不再更新界面。

边界：正在执行的同步 Binder 调用不能因线程中断而被保证取消。队列隔离避免它阻塞其他模块，不表示已解决所有厂商服务挂起问题。后续如发现长时间不返回，应增加诚实的超时状态和恢复入口，不能把超时显示成操作失败或自动重试清除。

### 预览渲染基础优化

模糊背景在壁纸后台加载阶段预先生成，随壁纸一起交给界面；退出 Magic Desktop 不再立即丢弃这张最大边 160 像素的小图。壁纸更换时替换，视图释放时清理。首次尺寸不匹配仍有同步兜底，不宣称绘制路径完全没有计算。

复用投影绘制中的 RectF / Matrix，并补充软件预览位图的释放。保留原硬件实时绘制路径，没有强制添加整屏软件缓存或改动桌面卡片手感。

## 动效实施约定：供下一轮 6.1 Sol 使用

第一轮确定以下规则；第二轮已补齐最近任务进退场、移动、外观操作行和非内联滑块，实际显示效果仍待实机验证。

| 动作 | 约定 |
| --- | --- |
| 焦点移动 | 复用 MotionSpring / UiMotion；快速反向保留当前位置与速度，不能先归零 |
| 设置进入 / 返回 | 共用持续窗口；返回逆向过渡，恢复原行及滚动位置；最多两页参与过渡 |
| Magic Desktop | 投影连续可反向；调整参数只刷新必要内容；子页不能创建独立的保存规则 |
| 最近任务进入 / 退出 | 进入与退出是一对可反向动作；只有完成退出才隐藏，Home / Activity 销毁可立即清理 |
| 最近任务刷新 | 不重新播放整页进入动画，不重置选中任务，不等待整批截图 |
| 动画时长 | 明确全局默认与局部覆盖关系；保留已有用户自定义值，不在迁移时清空 |
| 异步完成 | 检查页面代次和所有者；旧回调不得抢焦点、重新打开页面或覆盖新预览 |
| 删除任务 | 不提前假装系统删除成功；失败保留卡片，避免重复提交 |

不能为“统一动画”同时重写桌面、页面栈和最近任务三个状态系统。建议先补普通操作行和非内联滑块，再处理最近任务的进退场及重入，逐项验证。

### 静态刷新和缓存的后续方案

静态桌面先记录每分钟实际重绘次数、主线程耗时和功耗相关状态。普通 HH:mm 时钟可按分钟边界调度，网络与播放状态由现有事件刷新；进入屏保后仍需保留低频位移，转场期间继续逐帧调度。不能直接把唯一每秒心跳删除，必须先核对它承担的其他刷新职责，并覆盖跨分钟、日期、时区及唤醒。

低内存缓存先比较零缓存与小预算缓存下重复返回桌面的耗时、峰值内存、GC 和回收情况；按应用堆及内存压力分级，优先可见和相邻图片。不在没有采样的情况下直接给所有 2GB 电视增加固定大缓存。性能档位应在这些数据稳定后实施，并保留用户手动覆盖。
